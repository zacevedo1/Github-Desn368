Design Decisions

From the start, I wanted the visual identity of this field guide to feel rooted in the world of The Apothecary Diaries. I chose a deep maroon and forest green palette because those colors reflect the imperial court setting — rich, serious, and layered with meaning. The cream and gold accent tones were pulled directly from traditional East Asian manuscript aesthetics, which felt appropriate for a story set in a fictionalized historical empire.

I selected Bona Nova SC as the primary typeface because its small-caps character gave the headings a formal, archival quality without feeling stiff. Every section heading uses font-variant: small-caps, which ties the typography back to that historical reference without needing ornate decorative fonts. The sidebar navigation was designed to feel like a bookmark system in a physical guide — narrow, dark, and always present.

For the hero section, I layered a full-width banner image with an absolutely positioned wordmark centered at the bottom edge. This decision was intentional: I wanted the title of the series to feel embedded in the landscape of the banner rather than just sitting above it. The result gives the top of the page a more cinematic, editorial quality that sets the tone before the reader scrolls into the content.

Technical Challenges

The most technically demanding part of this project was building a fully functional hamburger menu and sidebar toggle using only HTML and CSS — no JavaScript allowed. I solved this using the CSS :target pseudo-class. Clicking the hamburger icon navigates to #sidebar, which triggers #sidebar:target { left: 0 } to slide the sidebar into view. The close button links back to #, removing the target and sliding the sidebar back off-screen. Getting the z-index stacking and transition timing right took several iterations.

Another challenge was the active navigation state. I wanted the sidebar link to highlight green when the user was in the corresponding section, again without JavaScript. I used :has() to check whether a section's ID was the current :target and then style the matching anchor in the sidebar. This required carefully matching every section ID to its corresponding nav link href, and debugging cases where IDs had accidental spaces or mismatches.

The character card grid also gave me trouble early on. Only two images were rendering visibly at first, caused by a combination of a global img { width: 30% } rule being removed and min-width: auto on flex children causing overflow clipping. The fix was adding min-width: 0 to the fig element and switching the image to width: 100%; max-width: 130px so it scaled within its grid cell correctly.

Responsive Strategy

I used two breakpoints: a mobile breakpoint at max-width: 640px and a large desktop breakpoint at min-width: 1440px. The mobile breakpoint handles the most significant layout shift — the sticky sidebar becomes a hidden off-canvas panel, the 4-column character grid collapses to 2 columns, the media images stack vertically, and the author section shifts from a horizontal to a vertical layout.

On mobile, I wanted users to still have access to navigation without the sidebar taking up the whole screen. The hamburger menu handles this with a fixed icon at the top-left. The title bar (header h1) is also fixed on mobile so the page title and brand stay visible while scrolling through long content sections. I kept the banner image and wordmark in the normal document flow so they appear at the top of the page when the user first lands.

The desktop breakpoint at 1440px widens the sidebar from 210px to 300px and increases the padding and heading font size for larger displays. This ensures the layout doesn't feel cramped or stretched at very large screen widths, while keeping a consistent visual weight across the content area.

Learning Moments

This project taught me a lot about the difference between position: sticky, position: fixed, and position: absolute in practice. I had used them individually before, but this project forced me to think about how they interact — for example, why position: sticky stops working when a parent has overflow: hidden, or why a child set to position: absolute positions itself relative to the nearest positioned ancestor rather than the page.

Flexbox behavior also became much clearer to me through this project. I learned that flex children have min-width: auto by default, which can cause them to overflow their container even when overflow: hidden is set on the parent. Setting min-width: 0 explicitly was the fix I needed for the character grid, and understanding why that works helped me think more carefully about how flex layout resolves sizing conflicts.

CSS specificity was another concrete lesson. When I set .close-btn { display: none } globally, it was being overridden by the more specific .sidebar a { display: inline-block } rule. I had to change it to .sidebar .close-btn { display: none } to win the specificity battle. That one bug made the cascade feel a lot less abstract and gave me a better mental model for writing selectors intentionally.

Future Improvements

If I had more time, I would add smooth scroll behavior and animated section transitions as the user navigates through the guide. Right now the :target-based navigation jumps abruptly to each section. Adding scroll-behavior: smooth is a simple improvement, but I'd also explore using scroll-driven animations to fade sections in as they come into view, which would give the guide a much more polished, editorial feel.

I would also expand the content for each section significantly. The Story Overview and Historical Context sections currently rely on paragraph text alone. I'd like to add pull quotes, inline illustrations, and annotated image callouts — similar to how a real field guide or encyclopedia entry is laid out. Adding a position: absolute decorative element to each section (such as illustrated botanical borders or chapter markers) would also strengthen the themed visual identity.

On the technical side, I'd revisit the character cards and add a hover state that reveals a short bio for each character — potentially using a CSS-only approach with :hover and sibling selectors. I would also investigate whether a CSS-only scroll spy (keeping the active nav state in sync without :target) is achievable using the Intersection Observer API or a future CSS feature, since the current :target approach ties navigation state to the URL hash rather than actual scroll position.
